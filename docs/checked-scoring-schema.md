# Checked scoring: совместимость схемы генерации

Статус: исправлен способ передачи схемы; реальная проверка на Ollama пользователя
ещё требуется. Это не завершение этапа качества и не изменение балльной шкалы.

## Что подтверждено

В пользовательском логе после обновления до `5c1fc27`: 359 обычных тестов прошли,
восемь текстовых интеграционных случаев завершились HTTP 400. Во всех случаях:

```text
Failed to initialize samplers: failed to parse grammar
```

Массивы `attempts` пусты: программа не получила ответов о выполнении пунктов.
Следовательно, этот запуск не проверил качество понимания текстов моделью.
Это не прежняя ошибка окна контекста; в сообщении сервера нет превышения токенов.

## Причина изменения

`components_schema()` передавала всю Pydantic-схему, включая `maxLength: 6000`
у цитаты и `maxLength: 2000` у объяснения, внутри вложенных ограниченных массивов.
Большие ограниченные повторения при преобразовании JSON Schema в грамматику —
известный источник аналогичного отказа в llama.cpp (источники ниже).
Лог пользователя не указывает точный путь проблемного ограничения; внутренний
парсер его сборки здесь не запущен. Связь с конкретными двумя `maxLength` —
обоснованная гипотеза совместимости, которую должен подтвердить повторный запрос.

## Изменение строго ограничено

Из новой схемы, отправляемой в `format`, удаляются ТОЛЬКО два верхних ограничения
длины строк: `$defs.TextQuote.properties.quote.maxLength` и
`$defs.ComponentDecision.properties.reason.maxLength`.

Они остаются обязательными в локальных Pydantic-моделях: цитата не длиннее 6000
символов, объяснение не длиннее 2000. Пустые строки и неправильные типы также
по-прежнему отклоняются. Ответ длиннее лимита не обрезается для получения балла:
он не проходит проверку, допускается одна прежняя попытка исправления структуры,
затем `unable_to_check` и `null`.

Сохраняются `minLength`, типы, обязательные поля, `additionalProperties=false`,
перечни `check_id`, вердиктов и реальных текстовых `evidence_id`, точное количество
пунктов, максимум восемь цитат и ссылки `$ref`. Нет перехода к `format="json"`,
неструктурированному ответу или отключению схемы. Нет повторного запроса с менее
строгой схемой после HTTP-ошибки. Пустой набор текстовых источников не создаёт
пустой enum: это остаётся прежним поведением с локальной проверкой цитат.

Исходный текст работы, промпт, критерии, обработка пар, вычисление баллов и модель
не меняются. Другие режимы и визуальная схема не меняются. Локальная валидация
совпадения цитат с источниками выполняется после генерации как раньше.
Совпадение цитаты всё ещё НЕ доказывает верное понимание её смысла моделью.

В журнал добавлены `generation_schema_version=2` и `generation_schema_sha256`.
Версия профиля оценивания `CHECKED_SCORING_VERSION=1` и его хеш не меняются:
это ревизия транспортной схемы, не новая утверждённая шкала. Схема строится один
раз на логический запрос и используется без изменения при структурном повторе.

## Проверено локально

`tests/test_checked_schema.py`: **36 passed** на Linux / Python 3.13.5 /
Pydantic 2.13.4 / httpx 0.28.1 / pytest 9.0.2.

Проверены точные отличия схемы для всех пяти текстовых критериев с источниками
и без них, сохранность схемы Pydantic, ограничения длин/типов/пустых значений и
количества цитат, передача полного длинного текста без обрезки, проверка цитаты
длиной 6000, отказ на 6001, арифметика, валидный uncertain без повтора, поддельные
источники, дополнительные баллы/пункты, отсутствие fallback после HTTP 400,
сохранение исходных ответов в аудите и хеш реально переданной схемы.

В тестах используется настоящий код checked_text, моделей, конфигурации и
HTTP-клиента. Только HTTP-ответы заменены явным MockTransport. Исходный
checked_text до правки и использованные неизменённые модули сверены по Git blob
SHA с репозиторием. Дополнительно новые схемы проверены доступным локальным
JSON Schema-валидатором. Это не проверка компилятора грамматик Ollama.
Полный набор проекта, Windows/macOS, нативный парсер и реальные восемь LLM-тестов
здесь не запускались. Тесты качества, их входы и ожидаемые баллы не изменены.
Существующие студенческие документы и JSON в репозиторий не добавлены.

## Повторная проверка на Windows

В активированном окружении проекта:

```powershell
& {
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw "Не удалось обновить проект." }
    python -m pytest -m "not integration" -q
    if ($LASTEXITCODE -ne 0) { throw "Обычные тесты не прошли. Ollama не запущен." }
    $env:STUDENT_AI_CHECKER_NUM_CTX = "16384"
    $env:STUDENT_AI_CHECKER_RUN_OLLAMA = "1"
    $env:STUDENT_AI_CHECKER_TEST_ARTIFACT_DIR = "$HOME\Documents\StudentAIChecker\PR1\control-tests"
    python -m pytest tests\integration\test_checked_text_real.py -v -s
}
```

Нужен свежий `text-controls-*.json`, независимо от результата. Если HTTP 400 исчез,
но какой-либо случай всё ещё не прошёл, в журнале уже можно будет отличить ошибки
цитирования, структуры и смысла. Прежний отказ не считается успешно пройденным
тестом. До разбора контролей настоящий отчёт повторно не запускается.
Переустановка Python/Ollama, загрузка новой модели и изменение DOCX не требуются
для проверки этой правки. Разработка GUI и установщиков не начинается.

## Первичные источники

  отдельная локальная проверка ответа.
- https://github.com/ggml-org/llama.cpp/issues/26596 — сообщение об аналогичном
  `failed to parse grammar` для больших `maxLength` в составной схеме; это
  сообщение о воспроизведении на другой сборке, не лог компьютера пользователя.
- https://github.com/ggml-org/llama.cpp/issues/25923 — ограничения повторений
  при преобразовании длин строк из JSON Schema в GBNF.
