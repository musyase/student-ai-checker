# ПР1 — утверждённая шкала и проверка по исходному бланку

Преподаватель подтвердил предложенную шкалу 9 сентября 2026 года (сообщение 19:15:26 UTC).
`examples/pr1.criteria.approved.json` — точная копия согласованного черновика, без изменения требований и баллов.
Всего 25 баллов: 3 + 2 + 3 + 5 + 3 + 3 + 5 + 1. Перевод в оценки 2–5 НЕ утверждён.
Исторический черновик и `docs/pr1-criteria-draft.md` оставлены без изменений.

`examples/pr1.approval.json` фиксирует версию, дату и хеши критериев и чистого DOCX.
Хеш критериев считается по нормализованным Pydantic-данным; отступы и окончания строк JSON на него не влияют.
Хеш бланка считается по исходным байтам: пересохранённый DOCX может иметь другой хеш.
Запись утверждения — локальная запись решения преподавателя и контроль целостности, а не электронная подпись.
Файлы студента и его персональные данные в репозиторий не добавлены.

## Проверка на Windows

Сохраните чистый `ПР1.docx` и работу студента в отдельную локальную папку вне репозитория.
Не пересохраняйте чистый шаблон специально для запуска: используется утверждённая версия исходника.
Пример ниже предполагает, что файл работы называется `student.docx`.

```powershell
cd C:\Users\user\projects\student-ai-checker
.\.venv\Scripts\Activate.ps1
git pull --ff-only
python -m pytest -m "not integration" -q

$work = "$HOME\Documents\StudentAIChecker\PR1"
$result = Join-Path $work ("result-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".json")
student-ai-checker check --document "$work\student.docx" --template "$work\ПР1.docx" --criteria examples/pr1.criteria.approved.json --approval examples/pr1.approval.json --output "$result"
```

Файлы должны уже лежать в выбранной папке. Команда не создаёт и не подменяет работы.
В режиме бланка `--template` и `--approval` обязательны вместе. При несовпадении утверждённых хешей модель не вызывается.
Результаты всегда предварительные. `grade` остаётся `null`, `teacher_confirmed` — `false`.
При отсутствии балла хотя бы по одному критерию `proposed_total` остаётся `null`; `scored_points` — сумма только имеющихся баллов, не итог за всю работу.
Существующий файл результата не перезаписывается, в том числе если он появился во время запроса.

## Что реализовано

Поэлементное сравнение извлечённых абзацев и ячеек после нормализации пробелов, а также сравнение изображений по SHA-256 их реальных байтов.
Совпавшие с шаблоном элементы исключаются из списка доказательств, доступных ИИ. Evidence ID, текст и изображения оригинала не изменяются.
Ссылку на исключённую инструкцию нельзя использовать для выставления балла: её отклоняет валидатор.
Положительный балл не принимается со ссылкой только на метаданные документа.
Изменённые поля в квадратных скобках сохраняются как кандидаты в ответы.
Похожие на отредактированные инструкции фрагменты помечаются `ambiguous`; в этой консервативной версии их наличие требует ручной проверки без автоматических баллов.
Выявленные предупреждения извлечения также останавливают автоматическое сравнение, а не превращаются в ноль.

Проверка содержания оставшихся кандидатов выполняется настоящим Ollama через прежний клиент, JSON Schema, Pydantic и валидацию evidence.
Добавление или изменение элемента само по себе не доказывает правильность, выполнение задания или авторство.

## Границы проверки

Это экспериментальное поэлементное сравнение, не универсальное семантическое разделение любого DOCX.
Перефразированная инструкция, склеенные ячейки, совпадение короткого ответа с текстом бланка, изменённое или перекодированное изображение требуют внимательной проверки преподавателем.
Сильное перефразирование может не попасть под эвристику похожести. Текущие критерии должны содержать необходимые условия: полный исходный бланк не передаётся модели как набор доказательств.
Обрабатывается поддерживаемый extractor-ом основной body; это не гарантия полного понимания всех объектов OOXML.
Без `--template` и `--approval` старый CLI остаётся техническим режимом совместимости с предупреждением, а не подтверждённым оцениванием.
