# Контекст Ollama: отказ на реальной ПР1 и исправление

## Подтверждённая причина

9 сентября 2026 пользователь сообщил об отказе локального Ollama 0.33.3:

```text
request (5152 tokens) exceeds the available context size (4096 tokens)
```

Это размеры, сообщённые сервером, а не оценка токенов по числу символов. Старый клиент
передавал только `temperature=0`, не задавая `options.num_ctx`. Smoke-тест с маленьким
документом не проверял вместимость контекста для полного отчёта и восьми критериев.

## Изменение

- `Settings.ollama_num_ctx` и `OllamaClient.num_ctx`: по умолчанию **16384**.
- Каждый `/api/chat` получает `options.num_ctx`: текстовый, мультимодальный и structured запросы.
- Переменная `STUDENT_AI_CHECKER_NUM_CTX` задаёт другое положительное целое число.
  CLI и прямой integration test передают выбранное значение клиенту.
- В строке `Ollama request` выводится запрошенный `num_ctx`; это не подтверждение
  фактически выделенной памяти и не количество токенов входа.
- После успешной CLI-проверки выбранный размер записывается в
  `result.json` → `inference_options.num_ctx`.
- Ответ с `done=false` или `done_reason=length` не принимается даже при корректном JSON.
- Неверное значение контекста отклоняется до HTTP-запроса. CLI показывает понятную ошибку.

16384 выбрано с запасом относительно измеренных 5152 токенов, чтобы оставить место
для полного ответа по критериям, а не только вместить вход. Это не гарантия вместимости
любого отчёта и не автоматический расчёт бюджета токенов. Увеличение контекста требует
больше памяти; скорость и достаточность памяти конкретного Windows-ПК ещё не измерены.

Не меняются модель, текст критериев, их хеши, баллы, сравнение бланка и правила evidence.
Тексты и оба изображения передаются без сокращения. Клиент не повторяет отказ,
удаляя картинки, отключая JSON Schema или бесконтрольно увеличивая выделение памяти.
HTTP-ошибка не создаёт оценку или фиктивный успешный результат.

Настройка отправляется именно в запросе Student AI Checker. Не требуется менять
глобальные параметры Ollama, создавать копию модели или скачивать веса повторно.

## Windows: повторить реальную проверку

После `git pull --ff-only`, в активном окружении проекта:

```powershell
python -m pytest tests\test_config.py tests\test_ollama_client.py tests\test_ollama_errors.py tests\test_ollama_context.py -q

$env:STUDENT_AI_CHECKER_NUM_CTX="16384"
$work = "$HOME\Documents\StudentAIChecker\PR1"
$result = Join-Path $work ("result-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".json")
```

Повторите прежнюю команду `student-ai-checker check` со своей работой,
`--template`, `--criteria`, `--approval` и новым `--output "$result"`.
В строке запроса должно присутствовать `num_ctx=16384`.
Переменная действует в текущем PowerShell; без неё новое значение по умолчанию тоже 16384.
Не добавляйте исходники студентов и их JSON-результаты в GitHub.

## Что действительно проверено для этого изменения

В среде разработки: Linux, Python 3.13.5, httpx 0.28.1, pytest 9.0.2.
Указанные выше четыре файла тестов: **70 passed** (33 новых тестовых случая и 37 существующих).
HTTP-сервер заменён `httpx.MockTransport` только в тестах. Проверены конфигурация,
явная передача контекста во всех трёх путях клиента, сохранность длинных текстов,
обоих изображений и JSON Schema, ошибки настройки, отказ сервера и неполный ответ.
Проверены синтаксис изменённых Python-файлов и передача параметра в CLI статически.
Полный набор тестов проекта и настоящий Ollama с этой правкой здесь не запускались.
Отказ 400 на Windows требует повторного реального запуска; исправление не является
доказательством качества оценивания студенческих работ.
