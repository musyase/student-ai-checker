# Проверяемый расчёт текстовых пунктов — PR1 v1

Статус: **следующая проверяемая доработка ядра, этап качества остаётся открытым**.
Новый флаг: `check --checked-scoring`. Он взаимоисключающий с `--visual-review`
и `--per-criterion`; старые режимы не изменены. Нужны `--template` и `--approval`.

## Основание

Предыдущий реальный визуальный запуск распознал рисунок, но ошибся в текстовых
критериях: свободный выбор общего балла допускал несогласованный подсчёт,
дополнительное требование скриншота и пропуск реально заполненной пары.
JSON Schema проверяет форму результата, не истинность свободного объяснения.

## Что сделано

1. Для пяти критериев (`installation-report`, `familiar-app`, `add-button`,
   `usability`, `summary`) модель возвращает только решения по фиксированным
   пунктам: met / not_met / uncertain, дословные цитаты и объяснение в журнал.
   Числового балла в её схеме НЕТ. Сумму и статус критерия формирует Python.
2. Тексты пунктов — буквальные фрагменты уже утверждённых описаний. Их количество,
   сумма и допустимые суммы сверяются с исходными критериями. Требовать новый
   пункт «обязательный скриншот» нельзя: лишний check_id отклоняется.
3. Каждая цитата проверяется на совпадение с конкретным извлечённым абзацем или
   ячейкой после NFC и нормализации пробелов. Буквы, регистр и пунктуация не меняются.
   Ссылка на метаданные, исключённый бланк или несуществующий источник не принимается.
   Скобки в заполненной ячейке не считаются признаком отсутствия ответа.
4. Соответствия проверяются кодом по ключу из утверждённого критерия, без вызова
   модели. Поддержаны подчёркивания, пробелы, регистр кириллицы, несколько видов
   тире, разделители и перестановка номеров. Явный пропуск или неверная кириллическая
   буква дают 0 за пару. Дубликаты, латинские буквы вместо кириллицы, лишние/потерянные
   номера, несколько полей ответа, дополнительные слова и неподдерживаемая запись
   переводят весь критерий на ручную проверку. Нельзя выбрать удобный вариант.
5. На исходных двух DOCX локально выполнены настоящее извлечение, сравнение бланка
   и проверка соответствий: найдены все пять правильных пар, вычислено 5/5 без LLM.
   Исходные файлы и предыдущий JSON не изменены. Это не новая полная оценка работы.

Шкала 25 баллов и исходная запись утверждения не меняются. Профиль привязан к хешу
ПОЛНОГО набора критериев и точному хешу исходного бланка. Под другим заданием режим
откажется работать, а не применит ключ ПР1. В успешном JSON сохраняются версия и хеш
технического профиля, результаты пунктов, проверенные цитаты, сырые ответы и ошибки.
Профиль не является новой электронной подписью преподавателя или новой шкалой.

## Границы этого изменения

Это **не универсальное завершённое оценивание** и не детерминированное понимание языка.
Совпадение цитаты доказывает, откуда взят текст, но НЕ правильность её интерпретации.
Модель по-прежнему может неправильно выбрать met/not_met/uncertain. Такие ошибки
нужно проверять содержательными контролями; одно правильное сложение их не устраняет.
Свободные объяснения модели хранятся как `model_reason_unverified` в локальном аудите.
Итоговое объяснение расчёта строит код. `student_feedback` для новых текстовых решений
пока пуст, а не выдаёт непроверенные обвинения как готовое сообщение студенту.

Два визуальных критерия продолжают использовать прежний VisualReviewChecker v3.
Проверка рисунка не переписывается в этом изменении. В подтверждении установки
результат ниже полного балла дополнительно передаётся преподавателю: старое
предложение сохраняется в аудите, но автоматическое снижение пока блокируется.
Это консервативное ограничение автоматизации, НЕ доказательство исправления смысла.

Для «Добавить» полный допустимый текст даёт рассчитанный балл БЕЗ обязательной
картинки. Если текст неполон и в работе есть картинки, новая ветка не отрицает
разрешённую визуальную альтернативу: итог критерия остаётся без балла до ручной
сверки. Полная автоматическая обработка этой альтернативы в новый расчёт ещё не
перенесена. Нельзя считать это исправлением всех случаев заданий с изображениями.

При uncertain хотя бы одного пункта сумма родительского критерия — null; известные
баллы пунктов видны только в аудите. Невалидный ответ можно исправить один раз;
HTTP-ошибки не повторяются, валидный uncertain не перезапрашивается ради балла.
Технические ошибки не заменяются нулём. Преподаватель ещё не подтверждал результат:
в выходном файле по-прежнему `grade=null`, `teacher_confirmed=false`.

## Проверки этой доработки

В текущей среде Linux / Python 3.13.5 / Pydantic 2.13.4 / httpx 0.28.1 /
python-docx 1.2.0 / pytest 9.0.2 выполнены:

```text
tests/test_checked_scoring.py
tests/integration/test_checked_text_real.py
54 passed, 8 skipped
```

Unit-тесты используют настоящий код нового расчёта, старые модели, extractor,
сопоставление бланка и HTTP-клиент. Только HTTP-ответы и делегат неизменённого
визуального режима в тесте сборки заменены явно обозначенными doubles.
Проверены негативные случаи, неизменность источника, хеш профиля, ограниченные
повторы, арифметика, цитаты, ошибки и разбор пар. Проверен настоящий argparse-фрагмент
CLI в изоляции и compileall. Неизменённые использованные исходники, включая CLI
до изменения, сверены по Git blob SHA с `4f59d1e`.
Полный старый набор тестов и импорт/запуск полного CLI здесь не выполнены.
Попытка установить проектный pytest 8 не удалась из-за отсутствия сетевого доступа;
в среде пользователя обычные тесты нужно выполнить с уже установленным pytest 8.

Восемь skipped — настоящие opt-in проверки Qwen: полный, частичный, неверный и пустой
ответ после нажатия; правильные и неправильные исправления в ячейках со скобками;
полное и частичное описание работы. Ожидания проверяются только assertions, не
передаются модели. null не считается прохождением. Генерируются синтетические DOCX,
а не копии студенческой работы. Журнал содержит все ответы, включая неуспешные.
**Реальный Ollama в этой среде с новой процедурой не запускался.**

## Следующий шаг на Windows

В активном окружении проекта:

```powershell
& {
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw "Не удалось обновить проект." }
    python -m pytest -m "not integration" -q
    if ($LASTEXITCODE -ne 0) { throw "Обычные тесты не прошли." }
    $env:STUDENT_AI_CHECKER_NUM_CTX = "16384"
    $env:STUDENT_AI_CHECKER_RUN_OLLAMA = "1"
    $env:STUDENT_AI_CHECKER_TEST_ARTIFACT_DIR = "$HOME\Documents\StudentAIChecker\PR1\control-tests"
    python -m pytest tests\integration\test_checked_text_real.py -v -s
}
```

Нужен новый `text-controls-*.json`, даже при всех PASSED. До разбора результатов
этих контролей тот же отчёт снова не запускать. После них используется прежний
CLI с новым `--checked-scoring` вместо старого флага и НОВЫМ --output.
Никаких установок моделей, изменения DOCX или ручного создания критериев не требуется.

В GitHub добавлены только исходники, синтетические тесты и эта инструкция. Ни DOCX
студента, ни его текст, изображения, имя или JSON-результаты не добавлены.
GUI, очередь группы, агенты и установщики Windows/macOS на этом шаге не создаются.

Справка для реализации: https://docs.ollama.com/capabilities/structured-outputs
(JSON Schema через format и отдельная локальная валидация ответа).
