# Раздельный визуальный анализ и оценивание

Статус: реализация для проверки качества ядра, не закрытие этапа и не начало GUI.
Включение: `student-ai-checker check --visual-review ...`.
Флаги `--visual-review` и `--per-criterion` взаимоисключающие; старые режимы сохранены.

## Основание

В последнем пользовательском запуске `--per-criterion` получен файл результата,
но рисунок опять остался без балла, а текстовый критерий изменился с полного балла
на ручную проверку. Причину нового решения нельзя определить по краткому логу.
Отдельная предыдущая диагностика тех же изображений прочитала существенные надписи,
но содержала ошибки пространственного описания. Поэтому одного разбиения критериев
недостаточно, а существование evidence ID не доказывает истинности замечания.
Ранее формулировка «Этап 1 закрыт» относилась к технической интеграции и была слишком
широкой: готовность качества оценивания этим не подтверждена.

## Новая схема

1. Прежний extractor разбирает DOCX; проверяется запись утверждения полного набора
   критериев и исходного бланка. Совпавшие инструкции по-прежнему исключаются.
2. Для критерия с разрешёнными изображениями **каждое** изображение-кандидат передаётся
   отдельно: один критерий, одни оригинальные байты, никакой истории чужих ответов,
   названий исходных файлов, текста студента или ожидаемого балла.
3. Модель возвращает наблюдения, видимые надписи, относимость к критерию, читаемость
   и конкретные сомнения. Она не назначает баллы на этом этапе. ID, SHA-256 и связь
   с критерием назначает код, а не модель. Это прямой vision-запрос с оригинальными
   байтами, не анализ по названию или чужому ранее сохранённому описанию.
4. Синтез по одному критерию получает весь доступный текст и полученные для него
   визуальные наблюдения. Это текстовый запрос: он не получает все картинки одновременно.
   В промпте это явно указано. Наблюдения помечены как НЕДОВЕРЕННЫЙ вывод модели,
   не получают новых evidence ID и не объявляются извлечённым текстом документа.
5. Итог проходит строгую схему, Pydantic, проверку исходных ID, согласованных баллов,
   статусов, бланка, типа доказательств и консервативные визуальные ограничения.
   Все баллы предварительные, `grade=null`, `teacher_confirmed=false`.

Для критериев, требующих только текст/таблицы, vision не вызывается и изображения
не используются как доказательства. Решение основано на `evidence_requirements`,
а не на имени студента или конкретных ответах. Если виды доказательств не указаны,
изображения не исключаются. Текстовые альтернативы не удаляются.
Для текущей ПР1 это 8 запросов синтеза и 6 отдельных визуальных запросов (3 критерия
с изображениями × 2 картинки), без учёта единственной разрешённой попытки исправить
невалидную структуру каждого логического запроса. Все вызовы последовательны,
модель и num_ctx прежние. Это не бесконечные агенты и не голосование за больший балл.

## Ограничения и защита

- JSON Schema ограничивает criterion_id/title/max_score/allowed_scores/evidence_ids,
  но не доказывает истинность свободного объяснения модели.
- Существенная нечитабельность или неопределённость визуального источника не заменяется
  нулём. Балл на сомнительной картинке блокируется, спор передаётся преподавателю.
- Положительный балл нельзя подтвердить только метаданными или исключённым бланком.
- При отказе отдельного визуального запроса соответствующий критерий остаётся
  `unable_to_check` без балла. Даже если текстовая альтернатива могла бы помочь,
  этот первый вариант консервативно оставляет критерий преподавателю.
- Невалидный JSON можно исправить один раз. HTTP-ошибки не повторяются с удалением
  картинок или произвольным увеличением памяти. Валидный `null` не перезапрашивается.
- Ошибка одного критерия сохраняется в результате, не стирая завершённые критерии.
  Это программный статус ошибки (`application_error`), а не фиктивный ответ ИИ.
  Отмена Ctrl+C и ошибка подготовки всё ещё прерывают запуск; возобновления пока нет.
- В JSON `visual_review.criteria` сохранены привязки изображений, наблюдения,
  попытки синтеза и происхождение результата (`model`, `application_error`,
  `application_safety_guard`). Это локальный журнал проверки, не новые доказательства.
- Код 0 CLI означает, что файл сохранён, а не что все пункты получили баллы.
- Ошибочное, но уверенное наблюдение модели всё ещё возможно. Архитектура устраняет
  одновременную подачу нескольких картинок, но сама по себе не гарантирует верное
  оценивание. Качество необходимо проверить на настоящем локальном запуске.

Предыдущие результаты не загружаются в промпты и не перезаписываются.
Содержимое студенческих файлов и сами диагностические результаты в GitHub не добавлены.
Критерии, шкала 25 баллов и запись утверждения не изменены.

## Проверка

В рабочей копии на Linux / Python 3.13.5 / Pydantic 2.13.4 / httpx 0.28.1 / pytest 9.0.2:
`tests/test_visual_review.py` — **61 passed**. Реальные extractor, сравнение бланка,
HTTP-клиент, валидаторы и CLI; HTTP заменён `httpx.MockTransport` только в тестах.
Проверены изоляция оригинальных изображений, отсутствие подсказок из работы в vision,
сохранность текста/таблиц, неизменность источника/критериев, ограниченные повторы,
ошибки без нулей, недопустимые ID/баллы/статусы, сомнительные изображения, отмена,
текстовая альтернатива, журнал JSON, совместимость записи утверждения и запрет перезаписи.
Исходные зависимости рабочей копии сверены по blob SHA с GitHub. Проверены компиляция
Python и `check --help`. Полный прежний набор тестов в этой среде не запускался.
Требуется запуск всего набора в рабочем окружении пользователя с зависимостями проекта.

Дополнительно добавлен **настоящий**, opt-in тест
`tests/integration/test_visual_review_real.py`: два синтетических изображения и
положительный/отрицательный контроль цвета. Он требует реальные баллы 1 и 0
в заведомо простых случаях: одних HTTP 200, корректного JSON или сплошных `null`
недостаточно, чтобы пройти его. Этот тест здесь **не запускался против Ollama**;
без opt-in пропускается. Он не заменяет оценку реальных студенческих работ.

## Команды

```powershell
git pull --ff-only
python -m pytest -m "not integration" -q
$env:STUDENT_AI_CHECKER_NUM_CTX = "16384"
```

Запустить прежнюю команду проверки, заменив `--per-criterion` на `--visual-review`
и выбрав НОВЫЙ путь результата. Загрузки нового ИИ и изменения файлов работ не нужны.

Для отдельной проверки простых семантических контролей:
```powershell
$env:STUDENT_AI_CHECKER_RUN_OLLAMA = "1"
python -m pytest tests\integration\test_visual_review_real.py -v -s
```

## Условия завершения текущего этапа качества

Не закрывать этап только из-за отсутствия исключений или увеличения суммы баллов.
Нужны: отсутствие известных блокирующих ошибок на текущем отчёте; отрицательные
контроли (пустой бланк, другое/отсутствующее изображение, неполный ответ); корректная
ручная проверка при повреждении; проверка, что инструкции из работы не меняют шкалу;
сравнение нескольких обезличенных работ и повторов с ручной оценкой преподавателя.
Для вывода о качестве нужен набор 10–20 работ, а не один удачный ответ. Не подгонять
prompt под конкретные ответы и не выбирать максимальную оценку среди повторов.
Это не требование абсолютной безошибочности на всех будущих документах: неизвестные
и спорные случаи должны оставаться видимыми преподавателю. GUI, SQLite-очередь и
установщики Windows/macOS пока не начинаются по последнему решению пользователя.

Официальная API-документация: https://docs.ollama.com/capabilities/vision и
https://docs.ollama.com/capabilities/structured-outputs .
