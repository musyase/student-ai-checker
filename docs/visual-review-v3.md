# Visual review v3: видимость признака и переносимость PNG-тестов

Статус: исправлены выявленные программные места; качество Qwen с новым контрактом
ещё необходимо проверить на реальном Ollama. Этап оценивания одной работы не закрыт.
Режим по-прежнему `check --visual-review`, модель и настройки контекста не меняются.

## Основание: два независимых сбоя

В присланном логе обычные тесты: 269 passed, 1 failed. Ошибка — сравнение SHA-256
сжатого синтетического PNG с константой из другой среды. В стандартной Windows-сборке
Python 3.14 zlib реализован через zlib-ng. Отождествлять байтовое представление
сжатого потока с пикселями некорректно. По одному логу нельзя доказать конкретную
версию библиотеки на ПК или побайтовую идентичность декодированных картинок.

Новый тест проверяет PNG signature, CRC каждого блока, IHDR (256×192, RGB8), структуру,
распакованные строки и КАЖДЫЙ ожидаемый пиксель. Сам генератор `_solid_png`, параметры
двух изображений и реальные ожидания 1/0 не изменены. Проверены разные уровни сжатия:
разные хеши контейнера при одинаковых пикселях допустимы; изменение пикселя, размеров,
фильтра или повреждение файла по-прежнему обнаруживается. Это узкая утилита тестовых
RGB8/filter-0 PNG, не новый универсальный декодер и не способ оценивать студента.
Хеширование исходных DOCX и извлечённых изображений в production не изменялось.

В реальном визуальном контроле положительный случай прошёл, отрицательный — нет.
Аудит показал: синтез уже предложил 0; guard отклонил его, поскольку обе записи
наблюдений содержали `readability=unreadable` и blocking с одной только подписью
«Цвет изображения». При этом описания уверенно называли видимые цвета и отсутствие
требуемого признака. Это противоречивый выход визуальной стадии, а не повод принять
0 вопреки переданной существенной неопределённости или отключить guard.

## Изменение контракта наблюдений

- Вместо двусмысленного `readability` используется `visual_access`:
  `clear` — визуальных данных достаточно, включая возможность установить отсутствие;
  `limited` — часть нужных данных скрыта/неразличима; `unavailable` — нужные данные
  определить невозможно. Это не наличие надписей и не выполнение критерия.
- В JSON Schema сначала идут description, visible_text, observations, затем
  relevance, uncertainties и visual_access. Сначала требуется описание наблюдений,
  а не преждевременный общий ярлык качества.
- Каждое сомнение содержит detail (какая деталь не установлена), cause (почему)
  и impact. Пустая причина или повтор названия детали отклоняются валидатором.
  Программная проверка не умеет доказать истинность причины или всех наблюдений.
- Старый JSON v2 с readability не конвертируется автоматически и не принимается
  как v3. `finding_schema_version` и `VISUAL_PIPELINE_VERSION` равны 3.
- Сохраняются raw attempts и ошибки структуры; guard дополнительно сохраняет
  blocking_causes. Числовой ответ синтеза не подставляется вместо null.

Границы не ослаблены: при конкретной существенной неопределённости блокируются
как неподтверждённые положительные, так и отрицательные баллы. Одно исправление
невалидной структуры разрешено, HTTP-ошибка не перезапрашивается, валидный null
не запускает поиск более высокого балла. Нет сопоставления свободного текста с
ожидаемым цветом в production, нет особого случая для контрольного теста или студента.
Каждое изображение всё так же передаётся оригинальными байтами отдельно.
Критерии, шкала 25 баллов, подписи/ID доказательств и старые результаты не изменены.

или обычные тесты завершились ошибкой:

```powershell
& {
    git pull --ff-only

    python -m pytest -m "not integration" -q
    if ($LASTEXITCODE -ne 0) { throw "Обычные тесты не прошли. Контроль Ollama не запущен." }
    $env:STUDENT_AI_CHECKER_NUM_CTX = "16384"
    $env:STUDENT_AI_CHECKER_RUN_OLLAMA = "1"
    $env:STUDENT_AI_CHECKER_TEST_ARTIFACT_DIR = "$HOME\Documents\StudentAIChecker\PR1\control-tests"
```

не меньше баллов. До проверки контролей отчёт повторно не запускать.
