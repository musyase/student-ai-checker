# Изображение существует, но модель сообщает об отсутствии

Статус: добавлена диагностика, **не исправление точности оценивания**.
Основной `student-ai-checker check`, утверждённые критерии и старые JSON-результаты не изменены.

## Что установлено

В предоставленном результате модель выбрала `insufficient_evidence` для рисунка,
сослалась на существующий ID изображения и при этом заявила, что рисунка нет.
Локальная сверка оригинального DOCX с результатом подтвердила хеш документа,
хеши обоих изображений и наличие второго изображения среди кандидатов в ответы.
Ручной просмотр второго PNG показывает рисунок экрана. Таким образом, замечание
об отсутствии рисунка неверно. Это не доказывает конкретную причину ошибки модели.

Текущая проверка evidence ID подтверждает существование источника, а не истинность
всех утверждений модели об этом источнике. HTTP 200 и правильный JSON не равны
правильному пониманию изображения. Прежние smoke-тесты не были оценкой качества vision.

## Изолированная проверка

Новый отдельный модуль: `python -m student_ai_checker.diagnose_images`.
Для каждого изображения он последовательно выполняет два независимых запроса:

1. Только одно оригинальное изображение и нейтральная просьба описать видимое,
   без JSON Schema, через прежний `chat_multimodal`.
2. То же изображение отдельно и та же нейтральная задача в простой JSON Schema,
   через прежний `chat_structured`.

Для двух изображений это четыре последовательных вызова одной локальной модели.
Текст работы, подписи, критерии, прошлые ответы модели и названия файлов не входят
в запросы. Правильный ответ и баллы не подсказываются. Изображения не увеличиваются,
не обрезаются и не перекодируются. Evidence ID связывается с байтами приложением,
а не генерируется моделью. Чужая история запросов не добавляется.

Новый JSON содержит исходный ID, SHA-256 байтов, размер, выбранную модель, контекст,
оба ответа и ошибки запросов/структуры. `model_output_is_untrusted=true`: это
утверждения модели для ручной проверки, а не новое достоверное evidence и не оценка.
Диагностика не вызывает grading-сервисы и не подтверждает результат преподавателя.

`--reference-result` проверяет хеш DOCX и идентичность упомянутых в старом результате
изображений до обращения к модели. Старый ответ не используется как подсказка.
При несовпадении запуск останавливается. Все данные остаются вне GitHub.
Loopback-адрес обязателен; системные HTTP-прокси и перенаправления отключены.

## Запуск в Windows

Из корня проекта в активном виртуальном окружении, после `git pull --ff-only`:

```powershell
python -m pytest tests\test_image_diagnostics.py -q
$work = "$HOME\Documents\StudentAIChecker\PR1"
$diag = Join-Path $work ("image-diagnostics-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".json")
python -m student_ai_checker.diagnose_images --document "$work\student.docx" --reference-result "$work\previous-result.json" --output "$diag"
```

Замените два входных имени на настоящие локальные имена. `--reference-result`
необязателен; для разбора уже полученной проверки рекомендуется его указывать.
Используются текущие настройки модели и `STUDENT_AI_CHECKER_NUM_CTX` (по умолчанию 16384).
Никакой загрузки новых весов не происходит. Новый файл не перезаписывает существующий.
Описание модели может содержать персональные данные со скриншота: не коммитьте
диагностический JSON и не публикуйте его без проверки.

Коды завершения: 0 — запросы вернули ответы требуемого формата (не гарантия их
правильности); 3 — файл сохранён, но в нём есть ошибка запроса или структуры;
2 — ошибка входных файлов/настроек/сохранения; 130 — отмена.
Ноль извлечённых картинок не доказывает отсутствия неподдерживаемых объектов:
смотрите `extraction_issues` и ограничения исходного extractor.

## Как интерпретировать

Если отдельное изображение описывается верно, а при оценивании целого отчёта
игнорируется, следующим кандидатом на изменение будет организация запросов по
изображениям/критериям. Это ещё не доказывает, что причина только в количестве картинок.
Если plain и structured отличаются, отдельно проверяются форма ответа и устойчивость.
Если оба отдельных запроса ошибочны, далее проверяются vision-модель, масштаб
изображения и воспроизводимость. Менять сразу несколько факторов и считать один
удачный ответ доказательством надёжности нельзя.
Ни один исход не даёт программе права заменить балл или обвинить студента.
