# ПР1: проект критериев для задания и отчёта в одном DOCX

**Статус: НЕ УТВЕРЖДЕНО преподавателем. Оценка студенту не выставлялась.**

Файл проекта критериев: `examples/pr1.criteria.draft.json`.

Источник требований — предоставленный преподавателем чистый шаблон `ПР1.docx`, «Практическая работа № 1. Знакомство с Android Studio и экраном приложения».
SHA-256 исходного шаблона: `c2193a2dccad9fbd04837e3f5a899cf07999b1734cc1dcaf4166779a7bd89956`.

Схема баллов ниже предложена при подготовке критериев: в исходном задании такой шкалы нет. Она требует отдельного согласования. Назначение баллов, отказ от отдельных штрафов за оформление и способ учёта неполных ответов — предлагаемые правила оценивания, а не дополнительные цитаты из задания. Итоговая шкала оценок 2–5 ещё не утверждена.

## Формат работы

Преподаватель выдаёт один общий исходный DOCX. Каждый студент сохраняет личную копию, заполняет ответы и вставляет изображения в неё. Отдельный отчёт не нужен; это прямо указано в шаблоне.

Чистый шаблон — источник задания, а не образец правильного выполнения. Заполненная студентом копия — сдача. Их не нужно вручную разделять на «задание» и «ответы» или очищать от исходных инструкций.

## Предложенная шкала: 25 баллов

| Раздел | Максимум |
| --- | ---: |
| 1. Ход работы с Android Studio | 3 |
| 1. Подтверждение достигнутого этапа | 2 |
| 2. Анализ знакомого приложения | 3 |
| 3. Экран «Мои задачи» | 5 |
| 4. Результат нажатия «Добавить» | 3 |
| 5. Три улучшения понятности экрана | 3 |
| 6. Соответствие понятий и объяснений | 5 |
| Итог работы | 1 |
| **Всего** | **25** |

Подробное распределение внутри критериев записано в JSON. Для трёх действий пользователя в задании 2 предложен один балл за полный блок из трёх различимых действий; это отдельное решение преподавателя при утверждении шкалы.

## Обязательные различия при проверке

- Неизменённые инструкции, названия разделов, готовые определения и подсказки — контекст, но не подтверждение выполнения.
- Студенческий ответ внутри квадратных скобок не считается пустым только из-за скобок. Сравнивается содержание поля, а не наличие символов `[]`.
- Для задания 5 проверяются заполненные ответы в столбце «Как исправить», а не исходное описание проблем.
- Для задания 6 проверяется заполненная строка соответствий. Ключ, выведенный из таблицы исходного задания: `1 — В; 2 — Г; 3 — А; 4 — Д; 5 — Б`. Сама неизменённая таблица определений не является ответом.
- Рисунок оценивается по изображению или по прямо разрешённой текстовой альтернативе. Перечень элементов экрана в условии не доказывает наличие рисунка.
- Снимок поиска программы не доказывает успешную установку, попытку установки или конкретную ошибку установщика. При неоднозначности требуется решение преподавателя, а не автоматически придуманный вывод.
- Незавершённая установка не должна сама по себе обнулять работу. Различаются отсутствие ответа студента и техническая проблема.
- В задании не требуется писать код или запускать приложение; эмулятор устанавливать не нужно.
- Задание допускает текстовые альтернативы в указанных случаях, не требует красивого оформления рисунка и не требует очистки поля ввода как единственного правильного решения.
- «Если закончили раньше» — дополнительный пункт. Сведения о напарнике относятся только к работе вдвоём. В этом проекте критериев они не превращены в обязательные пункты для каждого.

## Граница текущей реализации

На момент подготовки этого проекта CLI принимает `--document` и `--criteria`, но ещё не принимает отдельный исходный шаблон. Автоматическое сопоставление чистого бланка с заполненной сдачей не реализовано.

Фразы в описаниях критериев напоминают модели о разделении задания и ответа, но не заменяют программную защиту. Следующее изменение ядра должно добавлять сопоставление с выбранным преподавателем шаблоном: сохранять оригинальные evidence ID, помечать исходный текст и изменённые/добавленные элементы, не считать совпавшие инструкции доказательством выполнения. Изменённый элемент сам по себе тоже не является доказанно правильным ответом: содержание оценивается отдельно. Изменения формулировок студентом не изменяют утверждённые требования.

Не следует считать успешно пройденные smoke-тесты доказательством того, что текущая модель уже надёжно различает шаблон и ответы в реальных работах.

## Утверждение и приватность

`draft` в имени — отметка для разработчика и преподавателя; текущая модель `CriteriaSet` не имеет машинного статуса утверждения. Сначала преподаватель согласует критерии и баллы; после этого фиксируется утверждённая версия. Этот черновик не должен автоматически применяться как утверждённая шкала.

В репозиторий добавлены только обобщённые критерии и эта инструкция. DOCX студента, изображения из него, ФИО, его ответы и результаты оценивания сюда не добавлялись. Чистый DOCX также не добавлялся; для идентификации версии указан его хеш.
