# Диагностика HTTP-ошибок Ollama

## Изменение от 9 сентября 2026 года

В первом запуске реальной работы сравнение с бланком прошло, а локальный
`POST /api/chat` завершился HTTP 400. Старый клиент показывал только номер
HTTP-статуса и терял содержимое поля `error` ответа Ollama.
По одному HTTP 400 нельзя установить причину: это не доказательство ошибки
изображений, превышения контекста, несовместимости модели или нехватки памяти.

Исправлен **вывод причины отказа**, а не объявлена устранённой ещё неизвестная
ошибка на компьютере пользователя. Клиент теперь показывает:

```text
ERROR: Ollama вернул HTTP 400; причина Ollama: <поле error сервера>; автоматическая оценка не выполнялась.
```

Поддерживается штатная строка `error` и вложенная строка `error.message`.
Произвольное тело ответа (например HTML или отражённый JSON запроса) не выводится.
Диагностическое поле ограничено 600 символами; управляющие символы терминала и
длинные закодированные последовательности удаляются. Это не универсальное
обезличивание: короткий текст самого поля `error` также следует просмотреть перед
передачей третьим лицам. Диагностика не отправляется в облако и не подставляется
в инструкции модели или результаты оценивания.

Перед запросом логируются только количества: число изображений, их суммарный
размер, число символов обоих текстовых сообщений и наличие structured output.
`text_chars` — именно символы, НЕ количество токенов. Это не оценка расхода RAM/VRAM.
Тексты задания/ответов, содержимое JSON Schema и base64 изображений в этом логе
не печатаются.

Обработка HTTP-ошибки не повторяет запрос, не отбрасывает вторую картинку,
не заменяет модель, не меняет контекст, критерии или баллы. Отдельная существующая
попытка исправления некорректного ответа модели относится к валидации результатов,
а не к HTTP 400.
Также некорректная структура ответа и поле `error` при HTTP 200 больше не могут
быть приняты как нормальный ответ клиента.

## Повтор на Windows

Из каталога проекта с активным `.venv`:

```powershell
git pull --ff-only
python -m pytest tests\test_ollama_client.py tests\test_ollama_errors.py -q
ollama --version
```

Затем повторите прежнюю команду `check` со всеми теми же входными файлами и новым
именем `--output`. Ничего переустанавливать ради этого диагностического изменения
не требуется. Нужна полная новая строка `ERROR`, а не только код 400.
Содержимое студенческих файлов или полный журнал Ollama для первого шага не нужны.

При подтверждённой ошибке контекста размер окна следует менять осознанно,
с учётом памяти устройства; при ошибке изображения необходимо проверить именно
указанную сервером причину. Нельзя автоматически объявлять снимок отсутствующим
или ставить студенту ноль из-за технического отказа.

## Проверки

В среде разработки Linux, Python 3.13.5, httpx 0.28.1, pytest 9.0.2:

```text
python -m pytest tests/test_ollama_client.py tests/test_ollama_errors.py -q
35 passed in 0.32s
```

Это 3 существующих теста клиента и 32 новых диагностических/регрессионных случая.
HTTP-ответы в этих тестах — явные `httpx.MockTransport`, а не настоящий Ollama.
Проверены: сохранение поля ошибки, отсутствие HTTP-retry, разные форматы ошибок,
ограничение диагностического вывода, некорректный ответ сервера и сохранение
обоих изображений и JSON Schema в мультимодальном запросе.
Полный набор тестов проекта в этом изменении не запускался.
Реальный повтор нового клиента на пользовательском Windows ещё не выполнялся.
